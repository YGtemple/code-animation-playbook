# 踩坑全集（Pitfalls）

每一条都是真实踩过、且换风格时大概率还会再遇到的坑。格式统一为 **症状 / 根因 / 对策**。
新踩到坑请立刻追加到这里，保持"一处真相"。

---

## P1. 常量被同名函数覆盖 → 整片几何 NaN，元素静默消失

- **症状**：爆炸框多边形、集中线等元素"凭空消失"，但逐帧截图**不报错**，流程看起来一切正常。
- **根因**：本想写常量 `const P = Math.PI * 2`（2π），却误写成了同名函数 `const P = c => Math.PI * 2`。
  所有 `* P` 的坐标计算变成"乘一个函数对象"，结果全是 `NaN`。
  而 **SVG 对 NaN 属性不抛异常**，只在浏览器 console 打一条 warning，元素静默不渲染；无头截图自然也不报错。
- **对策**：
  1. 不要保留同名残留，常量 / 函数命名区分清楚；
  2. 渲染关键帧时**主动收集 `console` error 和 `pageerror`**（playwright 的 `page.on('console') / page.on('pageerror')`）；
  3. 自检里主动断言：遍历属性，**不允许出现字面量 `NaN`**，坐标类属性 `parseFloat` 不能是 NaN。

## P2. 声音里"时间偏移的包络"在触发点之前爆炸，归一化把整条音轨压没

- **症状**：合成出来的声音重击几乎听不见，整体非常小；查 RMS 一度只有 0.009。
- **根因**：snap 的第二声用了 `exp(-(t - 0.06) * 90)`。当 `t < 0.06` 时 `(t-0.06)` 为负、
  负负得正，指数**爆到约 156**。原始混音峰值因此高达 139；随后"按峰值归一化"为了压住这一个尖峰，
  把**整条音轨**等比缩小，正常的重击全被压没。
- **对策**：
  1. 任何带时间偏移的包络，**触发点之前必须置零**：
     `np.where(t >= onset, np.exp(-(t-onset)*k), 0)`；
  2. 归一化之前先查**原始混音峰值出现在哪个时间**、以及**整体 RMS**，不能只看单个峰值；
  3. 峰值异常大且位置不合理时，先修源头而不是靠归一化硬压。

## P3. 已定位元素被"双重 translate"推出画面

- **症状**：`请重试`、`验证通过` 等大文字 / 印章跑到画面外，看不见。
- **根因**：元素创建时已经放在 `x=CX`（已定位），`render` 里又给它 `transform="translate(CX ...)"`，
  两次位移叠加，文字被推到 x≈1920 之外。
- **对策**：
  1. 对**已定位**元素做缩放 / 旋转时，用"绕自身位置"的变换，不要再叠加位移：
     `translate(pos) scale(...) translate(-pos)`；
  2. 记住"定位"和"transform 位移"二选一，别同时用；
  3. 抽帧目检重点文字 / 印章是否在安全区内。

## P4. 高倍变焦 + 沸腾滤镜 + 多页面并发 → 整个浏览器崩溃

- **症状**：渲染到钻层 / 粉碎等高倍变焦段时，浏览器进程整体崩掉，context / page 全部失效。
- **根因**：feDisplacementMap 的沸腾滤镜在高倍变焦下计算量陡增，多个页面同时渲染把内存 / GPU 压垮。
- **对策**：
  1. 工作页面并发降到 **`WORKERS=2`**（可用环境变量调）；
  2. 启动参数加：
     `--no-sandbox --disable-setuid-sandbox --disable-dev-shm-usage --disable-gpu`
     `--js-flags=--max-old-space-size=1536 --renderer-process-limit`；
  3. 渲染器要能在 context / browser 死掉后**整体重启浏览器**并重试该帧；
  4. 配合**断点续渲**，重启后跳过已存在的帧，不重复劳动。

## P5. "死帧"超标（连续静止画面）

- **症状**：连续静止帧占比一度高达 **36%**（目标 ≤10%）。
- **根因**：
  1. 沸腾滤镜的 turbulence seed 若每 3 帧才换，3 帧组内必然出现两两相同的帧；
  2. 缺少运动的场景（6×6、贴纸、跳切间隙、结尾、横幅）会长时间完全静止。
- **对策**（在自检硬性要求下，对"每 3 帧换 seed"做了可控偏离）：
  1. 沸腾 **seed 每帧更新**；
  2. 给**每个可见场景**都挂沸腾滤镜；
  3. 开场加逐帧扫描噪点；光标等待时逐帧微抖；等待结果时整屏轻微推 / 拉。
  最终静止帧降到 **5.78%**。
- **刻意保留的静止**：失败弹窗的定格、结尾黑场是故意的笑点 / 收束，不算 bug——
  判断死帧要区分"意外静止"和"表达性静止"。

## P6. 开场黑场过长，把整段故障画面全遮住

- **症状**：开场的黑场一度盖到 0.98s，把前面精心做的故障画面全挡住了。
- **根因**：黑场淡出时长设得太长；而开场本身就是黑底故障，不需要再盖一层长黑。
- **对策**：只保留**前 0.12s** 从黑快速淡入，立刻露出故障内容。任何全屏遮罩都要核对它的时间区间，
  避免"遮罩吃掉正片"。

## P7. 字体下载路径 404 / GitHub API 限流

- **症状**：下载 Permanent Marker 字体 404；批量取文件时 contents API 频繁报限流。
- **根因**：
  1. Permanent Marker 在 google/fonts 仓库里**不在 `ofl/`**，而在 `apache/` 目录；
  2. GitHub contents API 有速率限制，批量调用容易 403。
- **对策**：
  1. Permanent Marker 用 `apache/permanentmarker/PermanentMarker-Regular.ttf`（`ofl/...` 是 404）；
  2. 直接拼 `raw.githubusercontent.com/google/fonts/main/<路径>` 下载，绕开 contents API；
  3. 字体随仓库本地存放（`fonts/`），渲染离线可用。

## P8. 换题材重渲后能量指标不达标（帧差偏低、黑+红面积偏低）

- **症状**：第二部首次成片 metrics 两项 FAIL——平均帧差只有 3.39（需 ≥6）、黑+红面积约 10%（需 ≥12%）。
  画面内容明明不少，但指标就是上不去。
- **根因**：新故事的构图/配色与第一部不同——本片大量"米黄底 + 中景小图标"，近黑与朱红占比天然偏低；
  且回合间存在较多"站定对峙"，仅靠沸腾抖动不足以把逐帧像素差拉过阈值。
- **对策**（两类指标分别补，最终帧差 6.13、黑+红 16.60%）：
  1. **补黑+红面积**：给舞台加一条贯穿各场景的**近黑地面**（深色椭圆/横带），既增对比又把角色"压住"，
     黑+红立刻升到 17% 上下；这是朋克片情绪浓度的快速来源。
  2. **补帧差（叠加多层"全片持续微动"）**：加大 world 的**呼吸式推/拉缩放**幅度；上调 `BOIL_SCALE`；
     让纸面 grain 的 turbulence **seed 逐帧变化**；再叠一层**持续漂移的全屏速度线**（数量/不透明度要够，
     太淡没用）。多层叠加才稳定越过 6，单一手段容易卡在 5 左右。
  3. **新引入的坑**：world 做呼吸缩放时，恰好铺满屏幕的 bg 矩形会在边缘**露出黑角**——
     把背景矩形**放大到屏幕之外**（如 x/y 负偏移、宽高加大）再做缩放，避免穿帮。
  4. 强沸腾会让文字/数字发虚，每次上调后先冒烟目检关键数字与印章的可读性，别为指标牺牲可读性。

## P9. 换风格后 metrics 失真：下采样插值、半透明、扫描线把"精确活性色"弄丢（像素/暗底通用）

- **症状**：像素片明明画面上有大块高饱和色，metrics 的活性色占比却偏低、反复 FAIL；帧差也对不上肉眼。
- **根因与对策（每条都实测过）**：
  1. **下采样必须用 NEAREST，不能用默认双三次/双线性**：受限调色板靠"精确色值盒"判定，
     双三次会把纯色块边缘糊成中间色、全部跌出色盒，活性占比被严重低估。重采样一律 `NEAREST`。
  2. **活性块用不透明实色，别用半透明闪烁**：opacity 闪到 0.85 会让 R/G/B 等比变暗、
     跳出严格色盒（如红 R 从 255 变 217）。要闪烁就切"实色↔隐藏"，不要调透明度。
  3. **扫描线 / 暗化遮罩要排除在指标外**：1px 扫描线会逐行压暗活性色、拉低占比并虚高帧差；
     指标在"舞台区、且不含常驻 HUD 与扫描遮罩"的口径下计算。
  4. **活性色要靠大面积填充块，细笔画撑不起占比**：放大 CRT 绿屏、KPI 实色条、高潮实色横带，
     文字描边再亮也只占很小面积。
  5. **静止帧判定要容纳刻意的 2 帧循环**：walk cycle / BOSS 呼吸是故意在两个 sprite 间切换，
     不应判死帧；改为"舞台区连续 ≥6 帧零位移才算静止"。
- **通用原则**：每换一套皮肤，第三条"情绪/对比色"指标必须按该风格的关键色与是否有羽化重写
  （见 restyling-guide / qa-checklist），并先在全分辨率下抽样核对真实占比，再相信下采样结果。

## P10. 暗底霓虹 NAA 虚高 / 水彩覆盖率量纲错位（两种新皮肤的指标坑）

### 暗底赛博（NAA）
- **坑1：氛围层过强把暗底"洗"进 halo 盒，NAA 反向虚高**。扫描线/辉光/噪点叠太重时，
  纯暗底被洗成暗青（如 (14,60,76)），恰好落进"紫 halo"宽盒，导致 NAA 显示 80%+ 的假达标。
  → 先把氛围层压暗（扫描线 opacity≈0.1、噪点 alpha≈0.05、外晕降透明度），让暗底占比回到 85%+，
  再测活性色；halo 宽盒要配合"暗底排除"一起用。
- **坑2：核心活性色靠细笔画撑不起 8%**。必须放**常驻不透明实色块**（加大霓虹落日、地平线、
  地面反射柱），再给每关补实色填充（实心印章、实色横条、交替实色 token），保证每帧基线。
- **坑3：最低活性帧被"白闪/结尾压暗"洗成 0%**。降低转场白闪强度；结尾 27s 起的主动熄灭、
  boot 黑帧按口径排除（它们是表达性收尾，不是缺色）。
- **坑4：帧差被辉光脉冲/扫描线灌水，或被 3×3 平滑洗掉真运动**。帧差用 **NEAREST 原始下采样差分**、
  不做平滑；氛围贡献压到有界；判定期（定格段）帧差最低，就加**真实内容运动**——
  循环横扫的扫描"带"（要够粗、下采样后仍可见）、文字心跳、网格滚动，而非加噪点。

### 水彩（HSV 覆盖率）
- **坑5：覆盖率量纲写错**。像素若已除以 255，阈值（如 ≥6）必须同量纲；量纲错位会让帧差/覆盖
  全部误判。先打印一帧真实数值范围再定阈值。
- **坑6：恒定色纸纹不产生逐帧噪点**。feTurbulence 后若 colorMatrix 输出恒定色，seed 变化也无差异；
  纸纹要做成真实噪点（保留 turbulence 的亮度起伏），否则弱沸腾在亚像素/下采样后不可见、帧差上不去。
- **坑7：弱沸腾位移太小，下采样后帧差只有 1–3**。逐级提高弱沸腾位移与频率 + 全局微抖 + 呼吸，
  但人脸/色块锁死；每次上调后目检 punchline 朱砂句仍清晰。

### 共性
- 换皮肤先做"全分辨率单帧数值诊断"：打印暗底/活性色/白字各自占比与代表像素值，确认色盒抓对了，
  再全量渲染；否则容易在"虚高"或"虚低"上盲目重渲多轮。

## P11. boil 关闭的"干净类"风格（扁平/孟菲斯）帧差必须用内容区口径，整帧 ≥6 是 boil 时代阈值

- **症状**：扁平片零噪点、boil 关闭、只靠真实 UI 运动，整帧平均 |ΔV| 只有 0.3–0.4，远低于旧阈值 6；
  但联系表显示每幕都在动、也没有长死帧。问题不在画面，在**指标口径没随风格改**。
- **根因**：旧"整帧均值 ≥6"靠的是 boil（feTurbulence 全屏位移描边）让画面处处在变。
  高留白、boil 关闭的风格里，运动只占画面很小一块，被大片静态白底/卡片一平均就趋近 0。
- **对策（内容区帧差）**：
  1. 构造内容掩码＝相邻两帧任一帧"非背景"像素（背景按该风格底色判定，如扁平 V>0.93,S<0.08），
     并膨胀 1–2px 纳入位移路径/扫掠块；
  2. 只在内容掩码内算 |ΔV|，并区分"有真实运动的帧"（设最小变化幅度，排除光标/描边抗锯齿灌水）；
  3. 阈值按实测重定（扁平：有运动帧内容区 ≥3、实测约 6），再配一条**真死帧**判据
     （内容区近乎无变化连续 ≤0.4s）兜底——这才真正区分"活着的干净片"与"死帧"。
- **对比**：孟菲斯同样 boil 关，但因 spring 弹动 + 全屏点阵/squiggle 漂移 + 硬币物理，
  活性像素帧差天然很高（实测 22）；扁平最克制，最需要内容区口径。
- **原则**：换皮肤三件事都要重看——活性色指标、帧差口径、静止阈值；并先在成片帧上实测分布再定阈值，
  不要把上一种风格的数字直接搬过来。

## P12. 网格块活性的几何对齐（包豪斯）与叠印通道分离（Riso）

### 包豪斯/瑞士（8×8 块口径）
- **坑1：下采样尺寸必须能被块大小整除**。270 不能被 8 整除会切出半块、统计错位；用 272（8×34）。
- **坑2：小元素在块口径下"看不见"**。细字/小方块填不满一个 8×8 块，再怎么跳也不计数；
  彩色覆盖与活性都要靠**大色块**（加大考核卡、常驻色块、进度条）。
- **坑3（核心手法）：放一个尺寸＝整数个块的"常驻 live block"**，让它每几帧在两个位置间跳，
  每次正好填满/清空确定数量的块（如 240×272＝1 块列×2 块行＝4 块），稳定越过"每帧动 ≥N 块"阈值。
  两个落点都要选在**任何场景卡片都不遮挡**的空档带，跳的方向避开卡片（如向左跳）；
  若被卡片盖住，那一整段就变死帧。
- **坑4：表达性段落要排除**。开场 0.12s 黑场、结尾署名段不计入"桶数/死帧"，否则误 FAIL。

### Riso（叠印/网点）
- **坑5：颜色合规必须先按专色通道分离**。两专色 multiply 叠印在整帧 RGB 里采样出莓紫中间色，
  若直接比色盒会把它误判成"第三专色跑色"；先分离 pink/blue/纸底 三层、再各自比对（叠印紫单列合法）。
- **坑6：metrics 自身 OOM**。逐块/连通域在高分辨率下吃内存，降低采样分辨率再算。
- **坑7：hold 段靠"读数逐帧跳 + 连续扫描线"补动**，且署名定格段从死帧判定豁免。

### 共性
- 网格/块类指标本质是"离散化后的状态计数"：先把尺寸、块几何、元素占块数在纸上算清楚，
  再让画面去对齐；靠肉眼微调很容易反复差"最后一块"。

## P13. TTS 中文旁白：对位、ducking、超时与双交付（v1.6 起）

> 这是对"纯代码、无生成式模型"在**人声一项**上的明确例外：画面 / 音效 / 配乐仍全部纯代码，
> 旁白允许且必须用 TTS（`text_to_audio_plus`）生成，再与纯代码床混音。

### 文案
- **克制、点睛，不把画面念满**：开场 1–2 句迅速交代"谁 / 在哪 / 什么处境"；关键转折一句帮观众跟上；
  结尾一句点题。单句短、总句数少；**包袱 / 反转的画面留给观众看，别提前剧透笑点**。
- 音色按片选：默认冷静、清晰、略带调侃；国风 / 民间片可换沉稳、温润、语速偏慢的说书音色。

### 生成与对位
- **逐句生成**（不要整段一次合成），才能把每句精确放到 cue 时间点；逐句裁去首尾静音。
- TTS 返回的可能是 mp3 / wav、采样率不一（常见 24k / 44.1k）、单声道：
  统一**重采样到 48kHz、单声道复制成立体声、居中（pan=0）**放置。
- 混音脚本读"纯代码床 + 各句人声"，人声单独走一条总线并测其单独 RMS。

### ducking（人声突出）
- 由人声区间生成包络：有人声处把床（配乐 + 音效）增益下压，**约 −9dB**；
  编曲较满 / lo-fi 床可压更深（−12～−18dB）；attack / release 平滑（如 0.06–0.15s / 0.18–0.3s），句间恢复。
- 编曲上把 **200Hz–2kHz 中频让给人声**（主旋律走高频、bass / 鼓走低频）；金句处让音乐收半拍、只留音效。

### 超时坑（最容易顶破 30s 硬顶）
- 固定时间点的句子若偏长，会在片尾叠加溢出 → **先量每句时长，在时间轴上预演**；
  放不下就对后段句子做 `atempo` 微加速（1.1–1.2，听感仍自然）和 / 或把起点前移，
  确保**最后一句在 30.0s 前结束**。片11 即对 V4/V5/V6 atempo 1.12/1.10/1.18 并前移 V5/V6。

### 响度与交付
- 人声居中、清晰、不被音乐盖住；最终整体**峰值 −1dBFS、不破音**；
  报告人声单独 RMS、旁白版 / 无旁白版各自 RMS 与峰值。
- **每片固定两版**：① 旁白版（配乐 + 人声，主推、可直接发布）；② 无旁白配乐版（同画面同配乐、无人声，备用）。
- TTS 人声目录（`voice/`、`voices/`）是生成物，已在 `.gitignore`，README 注明按文案重新生成；
  画面仍**不烧字幕**，上屏中文只保留 diegetic 的标题 / 印章 / 签文 / HUD。

## P14. 定格步进（黏土）与黑白胶片（默片）的指标重写；TTS 工具在子代理可能缺失（v1.7 起）

### 黏土 / 橡皮泥定格（2 帧一拍，pose 采样层）
- **坑1：逐帧差在"2 帧一拍"下必然半数为 0**。定格摆拍相邻两帧是同一 pose，旧逐帧差会把它整片误判死帧。
  → 指标改在 **pose 采样层**：`p_i = frame(2i)`（900 帧 / 2 = 450 pose），只在 pose 之间测形变。
- **坑2：测什么**。对主体颜色（如陶土橙 `#E8A87C ±12`）掩膜，提**质心位移、外接框高宽比（squash）、径向轮廓相关**；
  活 pose 阈值（质心 ≥4px / `1−corr ≥0.03` / `|Δsq| ≥0.025`，任一）。窗口 = 30 pose（1s），
  窗口 alive 需 ≥3 个活 pose，全片 alive 窗口 ≥0.85；剧本静止 beat 走**白名单 ≤20%**（结尾负鼠定格等）。
- **坑3：手工噪声只叠角色层、seed 按 pose 固定**。`feTurbulence 0.9/2` opacity 6–8% 只盖角色（背景纯色不做、省渲染）；
  轮廓 ±1.5px 扰动的 seed 必须**按 pose 编号固定**（同一 pose 的两帧完全一致），否则变成逐帧闪烁、又污染指标。
- 保"活"手法：每 4 拍呼吸 ±2% squash&stretch、静止 pose ±0.5px、被吸时整体向拽向压扁 5% 回弹；pose 硬切、无运动模糊。

### 黑白默片（先配准 → 扣颗粒本底 → 3σ 分桶）
- **坑4：颗粒 / 抖动全程存在，帧差会被灌水**。每帧时间不相关高斯颗粒 σ_g=7、gate weave 全局平移 ±2px。
  三步：① 相位相关估计全局平移并**配准**去抖动；② `D=|f_t−f'_{t−1}|`，扣颗粒本底
  `μ_g=σ_g·√(2/π)≈5.6`，`net_motion=D.mean()−μ_g`；③ 真运动阈值 `T=3σ_g√2≈30`，3×3 腐蚀后只算 >50px² 运动块。
- **坑5（反直觉）：静场 net≈0 是正常、不是死帧**。死帧要靠"角部平坦区实测颗粒 std 是否 ≈σ_g（6.25 左右）"判定：
  std<1 或帧字节完全相同 = 渲染 bug 死帧；颗粒还在、只是人不动 = 健康静场。
- **坑6：颗粒帧极占盘 / 占码率**。不要落颗粒 PNG：playwright 只渲干净内容帧，`filmify.py` 在管道里加灰度/颗粒/暗角并
  **直接 pipe 给 ffmpeg**；颗粒是噪声，编码 CRF 可放宽（CRF22→24，体积从 300MB 降到 ~30MB，肉眼无差）。
- 插卡（intertitle）是风格本体、不算烧字幕：黑底米白衬线、硬切、每张 1.6–2.2s、全片 ≤5 张。

### TTS 工具在子代理可能缺失（重要协作经验）
- **坑7：制作子代理的环境里 `text_to_audio_plus` 可能不可用**（调用不解析），子代理容易擅自改用 edge-tts / SAPI——
  这偏离用户点名的工具。**正确做法**：由 Organizer（本层，确认工具可用）亲自逐句生成旁白、下载后把**本地 wav 路径**
  交给制作代理重混重出；不要静默接受替代 TTS，也不要让子代理反复试工具。
- 旁白 wav 常带较多首尾静音（文件时长被 pad 到整数秒），由混音脚本统一裁剪、量真实时长、必要时仅对末句 atempo。

## P15. 青绿山水（文人画）与 VHS 模拟带的指标重写；颗粒类风格的码率爆炸；TTS 节奏（v1.8 起）

### 青绿山水（留白多 → 内容区口径 + 视差相位相关）
- **坑1：全帧差/全帧颜色在大面积留白下失效**。宣纸底占一半左右，全帧 diff 永远偏低、青绿占比被稀释。
  → 先 mask 掉宣纸底（与 `#F1E9D2` 距离<18），只在"内容区"统计青绿覆盖（绿+青合计≥70%、绿:青≈65:25）。
- **坑2：长卷横移怎么测"在动"**。近景 ROI(下40%)、远景 ROI(上40%) 分别做**相位相关**求横向 dx，
  三层视差应满足 `dx_near≈3×dx_far`（比值 2.6–3.4）、二阶差分<2px（匀速、无跳变）。
  推镜特写段近景会停，逐帧中位比值会被拉高——用**全片均值口径**，不要用中位。
- **坑3：墨线骨占比要压住**。Sobel/Canny 边缘 ∩ 深墨(R,G,B 均<90) 落在 [0.6%,2.2%]；
  线太细（<0.6%）山水发飘，太密（>2.2%）变线稿、失去青绿平涂。
- 远山降饱和向宣纸色混合，会让严格色盒的"青绿覆盖"略低于目标——属留白必然，视觉层次成立即可，不必硬凑。

### VHS 模拟带（YUV 域 chroma bleed + 磁噪三层分离 + 受控老化）
- **坑4：chroma bleed 必须在 YUV 里只糊 U/V**。转 YUV，对 U/V 只做**水平**高斯模糊 σ3–4px、**Y 不糊**
  → 颜色水平涂抹而轮廓仍清楚；若直接在 RGB 全通道糊，会把画面整体糊烂、失去"软但清楚"的 VHS 感。
- **坑5：暖漂 / 降饱和有先后顺序**。先降饱和再暖漂，暖漂量会被压缩、测不到目标（R−B +8~12）；
  **暖漂要放在降饱和之后**。颜色类指标改测三个"受控老化量"（bleed_px / drift_warm / saturation_lvl），是设计值、非缺陷。
- **坑6：磁噪灌水帧差**。同 P14 思路，D 拆三层：底部 tracking ROI(y≥1008) 单列剔出、3×3 高通测 grain σ(8–12)、
  去噪后 >3grain + 中值 + 连通域只保留 >0.3% 画面 blob 才算主体运动；grain/tracking 再大也不并进运动分。
  办公室静坐镜头（grain/tracking/REC 闪全程在）属健康静场，死帧阈值放宽到连续 45 帧(1.5s)。
- 重 glitch（撕裂/雪花/倒带）只在暂停、掉磁、倒带瞬间爆发；平时软、暖、克制，全程拉满=滤镜感、不可信。

### 颗粒 / 噪点类风格的码率爆炸（通用，重要）
- **坑7：颗粒、磁噪、胶片噪点是高频随机噪声，低 CRF 会让码率/体积爆炸**。VHS 在 CRF18 曾达 111Mbps、单文件 398MB。
  → 颗粒类风格**直接用高 CRF（24–26）编码**：噪声本身掩盖压缩损失，肉眼基本无损，VHS 压到 ~57MB、默片 ~30MB。
  干净扁平/矢量风格才需要低 CRF。交付前务必看文件大小与视频码率，别把 100Mbps 的"技术达标片"交出去。
- 噪点帧不要落盘：干净内容帧由浏览器渲染，老化/颗粒在 Python 管道里施加并直接 pipe 给 ffmpeg（省盘、省 I/O）。

### TTS 节奏：优先"重新生成"，重 atempo 兜底
- **坑8：TTS 按"语速偏慢"演绎会普遍超长、顶破 30s 或相邻句打架**。
  偏长的句子**首选**用"语速正常（偏快）、句子紧凑、不拖长"的指令**重新生成**（自然、无伪影）；
  只有末句等个别情况用 atempo（≤1.3）收紧。整片多句 atempo>1.3 会明显发假，应避免。
- 先按"每句真实语音时长 + 相邻句留 0.2–0.5s 气口、末句 ≤29.8s 收"反推起点，再让画面 beat 对齐人声。

## 调试方法沉淀（通用）

1. **让静默错误发声**：SVG NaN、字体回退等问题不抛异常，必须主动监听 console / pageerror，并做属性断言。
2. **联系表（contact sheet）目检**：把关键时间点缩成一张网格图，一眼扫出文字出界 / 元素缺失 / 数字错误。
3. **指标驱动**：用 `metrics.py` 把"画面有没有在动 / 情绪浓度"量化，不靠肉眼感觉。
4. **缩小爆炸半径**：改完只补渲染受影响帧，再重跑指标，最后才整片编码。
5. **先修根因，不要绕过**：崩溃 / NaN / 爆音都要找到源头，不靠重启 / 归一化 / 遮罩硬盖。

## P16. 波普漫画 Ben-Day 网点与手绘涂鸦的指标口径；TTS 由 Organizer 亲自生成（v1.9 起）

### 波普漫画（Ben-Day 网点做明暗 / 粗黑描边 / 分格爆裂框）
- **坑：网点覆盖率 `dot_cov` 在下采样口径下被混没**。Ben-Day 是 26px/15px/11px 间距的规则色点；下采样到 160×90（相当于约 12px 采样网格）时，
  网点与采样网格亚像素错拍、被 NEAREST 混为纸白，读数仅 ~3%，但 1080p 画面网点真实丰富。
  → **网点类指标必须在全分辨率（或按"网点占所在阴影区比例"）上量**，不要在 160×90 上判网点；阈值也要据此重基线，勿为凑数把点加大到画面发脏。
- **坑：明暗全靠网点、绝不用实心灰**。脸/身体暗部 = 纸白 + 红/蓝网点，最重阴影 ~70% 覆盖仍透纸白；一旦涂成 `#333` 实心灰就丢了 Lichtenstein 的印刷感。
  网点层用独立 rect + clipPath 限定在形状内；剂量升级靠**网点密度档位跳变**，不靠颜色渐变。
- **坑：生命感别靠 boil**。波普是"机械印刷品"，boil 手振会和 Riso 手工套印撞脸；关 boil，靠切格、爆裂框 scale 弹簧 punch(1→1.35→1/3帧)、
  气泡弹出(scale0→1/2帧) 保活。`panel_motion` 要裁掉边距/gutter 后只在内容区测爆裂框 3 帧内 ±30% 的面积跳变（全片 ≥8 次）。
- 描边纪律：主轮廓 12–14px、气泡 6–8px、panel 边框 8–10px；落地影 = 一团蓝密网点硬切，不画软投影。

### 手绘笔记本涂鸦（paper mask + 笔迹内容区帧差）
- **坑：横线/红 margin 竖线是固定背景，不 mask 就每帧误报"在动"**。先把纸色、横线、红竖线、便利贴底色一并 mask，
  只在笔迹内容区算 `content_diff` 与 `ink_ratio`；留白多，**不能用全局帧差≈0 判死帧**。
- **坑：`ink_ratio` 全片一刀切会误判**。记账明细页笔迹密集，会瞬时超 3.5% 上限（实测全片均值 4.93%、明细页更高），属该镜头表达性密度；
  阈值应按"分镜头基线"，正文页 0.6–3.5%、明细页单独放宽。
- 上屏字要"写出来"：逐字 opacity/书写入场（0.15–0.3s/字），不整段淡入；boil 全局关，只局部笔迹 ±0.5px 微抖。
  `ink_texture`（笔迹区拉普拉斯）须 > 干净矢量基线 1.5×，否则线条太直、不像手写。

### TTS 旁白：由 Organizer 亲自生成，禁止子代理用 edge-tts/SAPI 顶替
- **坑（再次出现）**：制作子代理环境里 `text_to_audio_plus` 可能不解析，子代理曾擅自改用 edge-tts。
  → **旁白一律由 Organizer 用 text_to_audio_plus 逐句亲自生成**，裁剪首尾静音、重采样 48k、按点铺好，再把本地 wav 路径与 voice_manifest.json 交制作代理重混；
  不接受 edge-tts/SAPI 顶替。
- 偏长句先用"语速正常偏快、紧凑"重新生成（自然无伪影）；末句等个别情况才 atempo（≤1.3）。
  末句若顶破 30s，优先**提前起点**（如片18 v6 由 28.3 提前到 26.3）而非加速到发假。
